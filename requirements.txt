# melody-miner — pip dependencies (single env, validated on Windows + py3.12 + CUDA).
#
# Install order matters — use scripts/setup_venv.sh, or manually:
#   python -m pip install -U pip setuptools wheel        # py3.12 needs new setuptools
#   pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
#   pip install --only-binary=numpy -r requirements.txt  # keep numpy as a wheel (see below)
#   pip install --no-deps basic-pitch==0.4.0             # see WHY below
#
# WHY the special flags (these ARE the fixes for the two dependency-conflict risks):
#   • numpy --only-binary : a transitive pin can drag in an OLD numpy *sdist* whose
#       build uses a setuptools that crashes on Python 3.12 (pkgutil.ImpImporter).
#       Forcing the numpy wheel (1.26.1 already ships a cp312 wheel) avoids the build.
#   • basic-pitch --no-deps (risk A): basic-pitch 0.4.0 hard-depends on tensorflow
#       <2.15.1 for py>=3.11, and that TF has NO py3.12 wheel → uninstallable, and TF
#       would also clash with torch/transformers. The ONNX model (nmp.onnx) SHIPS in
#       the wheel, so we install basic-pitch without its deps and supply onnxruntime
#       below; basic-pitch then auto-selects the ONNX backend (no TensorFlow needed).
#   • transformers PINNED 4.46.3 : 4.49+ refuse torch.load(.bin) on torch<2.6
#       (CVE-2025-32434). ContentVec (lengyue233/content-vec-best) ships as .bin, so
#       newer transformers would raise. 4.46.3 predates the guard and loads it fine.
#   • deepfilternet (risk B): OMITTED. Its `deepfilterlib` (Rust) has no Windows wheel.
#       The content encoder guards its absence (denoise = passthrough), and training
#       used skip_denoise anyway, so clean input is essentially unaffected. Install it
#       only on Linux/WSL if you need denoising of noisy mic input.
